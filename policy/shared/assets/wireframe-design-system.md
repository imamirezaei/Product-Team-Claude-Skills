# Wireframe Design System

This is the design system used exclusively for wireframe HTML output generated by the `wireframe-generator` skill. It is intentionally minimal — it conveys structure, hierarchy, and interaction states without resembling the final visual design.

Do NOT use the product's real design system (Vuetify, brand colors, custom components) for wireframes. Wireframes must look clearly unfinished so stakeholders focus on flow and behavior, not aesthetics.

---

## Purpose

- Communicate screen structure and information hierarchy
- Show all states: happy path, empty, loading, error, edge cases
- Allow navigation between states in a single HTML file
- Be readable in both LTR and RTL layouts (the product is RTL/Persian-first)

## Color Palette

Use grayscale only. No brand colors.

| Token | Value | Usage |
|---|---|---|
| `--bg` | #f5f5f5 | Page background |
| `--surface` | #ffffff | Cards, panels, modals |
| `--border` | #ddd | All borders |
| `--border-strong` | #aaa | Focused inputs, active elements |
| `--text-primary` | #111 | Headings, important labels |
| `--text-secondary` | #666 | Supporting text, captions |
| `--text-disabled` | #bbb | Disabled states |
| `--text-placeholder` | #999 | Input placeholders |
| `--accent` | #555 | Primary action buttons, active state |
| `--accent-light` | #eee | Secondary buttons, hover states |

| `--error-bg` | #fdf2f2 | Error message backgrounds |

| `--success-bg` | #f2fdf5 | Success message backgrounds |
| `--warning` | #e67e22 | Warning states |

## RTL Layout

The product is RTL/Persian-first. All wireframes must use `dir="rtl"`:

```html
<html dir="rtl" lang="fa">
```

Text alignment, flex direction, and padding must respect RTL flow. Use logical CSS properties where possible:

```css
padding-inline-start: 16px;   /* instead of padding-left */
padding-inline-end: 16px;     /* instead of padding-right */
margin-inline-start: 8px;
text-align: start;             /* instead of text-align: left */
```

## State Navigation

Every wireframe HTML file must include a state navigation bar so reviewers can switch between states without modifying the file.

```html
<div class="state-nav">
  <button onclick="showState('happy')" class="state-btn active">Happy Path</button>
  <button onclick="showState('empty')" class="state-btn">Empty State</button>
  <button onclick="showState('loading')" class="state-btn">Loading</button>
  <button onclick="showState('error')" class="state-btn">Error</button>
  <!-- Add one button per state defined by edge-case-finder -->
</div>

<div id="state-happy" class="state-view">...</div>
<div id="state-empty" class="state-view" style="display:none">...</div>
```

```css
.state-nav {
  position: fixed;
  top: 0; left: 0; right: 0;
  background: #222;
  padding: 8px 16px;
  display: flex;
  gap: 8px;
  z-index: 1000;
}
.state-btn {
  background: transparent;
  color: #ccc;
  border: 1px solid #555;
  padding: 4px 12px;
  border-radius: 4px;
  font-size: 12px;
  cursor: pointer;
}
.state-btn.active { background: white; color: #222; border-color: white; }
```

```javascript
function showState(id) {
  document.querySelectorAll('.state-view').forEach(el => el.style.display = 'none');
  document.querySelectorAll('.state-btn').forEach(btn => btn.classList.remove('active'));
  document.getElementById('state-' + id).style.display = 'block';
  event.target.classList.add('active');
}
```
